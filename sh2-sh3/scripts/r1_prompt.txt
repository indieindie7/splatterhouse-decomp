Sega Genesis game GAME (Namco 1992/93, side-scrolling horror beat-em-up: player Rick, punches/kicks/weapons, enemies, bosses, stages, health, lives, score). Round 1 of naming in Ghidra: FILE holds the Ghidra decompile (68000) of a slice of the program's functions. Most callees are still FUN_xxxxxxxx; evidence is hardware access, constants, data flow and call structure. Grep the full decompile FULL for callers of an address (search "FUN_000xxxxx") when it helps; Read FULL only with offset/limit.

Genesis memory map: ROM 0x000000.., Z80 RAM 0xa00000 (sound driver; writes there = sound commands), I/O 0xa10001 version, 0xa10003/0xa10005 pad data (TH select), 0xa10009.. pad ctrl, 0xa11100 Z80 bus request, 0xa11200 Z80 reset, VDP data 0xc00000, VDP control 0xc00004 (register writes 0x8xxx; VRAM/CRAM/VSRAM address commands like 0x40000000 VRAM write, 0xc0000000 CRAM write = palette, 0x40000010 VSRAM = vertical scroll; DMA = registers 0x93-0x97), HV counter 0xc00008, PSG 0xc00011, work RAM 0xff0000-0xffffff (game state, object tables, sprite attribute buffer).
Typical roles: vblank/hblank handlers, pad reading, DMA queue, sprite table build, scroll/plane drawing, tile/nemesis/other decompression, palette fades, object (actor) update dispatch by type through jump tables, player state machine, collision/hit boxes, damage/health, enemy AI, boss scripts, stage/scroll scripts, title/menu/options, sound command queue, random number generator, math (multiply/divide/sin).

For every function in FILE write exactly one line to OUT (Write tool):
- if you can characterise it: 0x<hex addr> func <name> hand <short evidence>   (unique C identifier, max 40 chars, prefixes: sys_, irq_, vdp_, dma_, pad_, z80_, snd_, spr_, pal_, scroll_, tile_, dec_, obj_, player_, enemy_, boss_, col_, dmg_, stage_, title_, menu_, game_, hud_, rng_, math_, mem_, txt_; add the address suffix _<hex> only if the same name would repeat)
- if it is clearly not code (decompile shows halt_baddata, bad instruction, data bytes, a body that starts mid-instruction or falls into another function): 0x<hex addr> bogus <reason>
- if it is real code but you truly cannot tell: 0x<hex addr> func <prefix>_unk_<hex addr> hand <what it does mechanically>  -- prefer a mechanical name (e.g. obj_set_field_1c, copy_16words) over unk.
Mark weak guesses by starting the evidence with "GUESS". No other lines, no blank lines. Use only Read/Write/Grep. Final reply: counts of func / bogus lines.
